# Arlo Design Notes

## Goal
Arlo should feel like a polished, real iOS app, not a generic AI-generated prototype.

## Core Design Formula
- Native patterns first
- One clear question per screen
- Limited visual vocabulary
- Clear hierarchy over decoration
- Progressive disclosure
- Short copy
- Minimal but premium feel

## Rules

### 1. Use native iOS patterns
- NavigationStack
- Lists/sections where appropriate
- standard sheets
- standard buttons
- system typography
- restrained animation

### 2. Today screen should answer three questions fast
- What matters today?
- What should I do next?
- What is done already?

### 3. Limit visual vocabulary
- one accent color
- one main container style
- one primary button style
- one secondary action style
- avoid too many card types

### 4. Avoid vibe-coded design traps
Avoid:
- random gradients
- too many shadows
- glassmorphism by default
- giant hero sections with no utility
- card soup
- too many badges/chips
- long AI-style copy
- chat transcript as the main UI

### 5. Copy should sound like a product
Good:
- Pull day. Leave in 20 min.
- Lunch at home: tofu bowl.
- You still need 2,800 steps.
- Tech brief ready.

Bad:
- Here is your personalized growth journey for today.
- Let’s optimize your life with these intelligent recommendations.

### 6. Use progressive disclosure
Keep the first layer simple.
Details should appear only when tapped.

### 7. Calm premium tone
Arlo should feel:
- calm
- competent
- direct
- lightly premium

Not:
- childish
- hyper-futuristic
- motivational in a cheesy way

### 8. Monochrome-first check
A strong test:
- if the screen still looks good mostly in neutrals plus one accent, the structure is probably good

### 9. Anti-vibe-code review checklist
Before keeping a screen:
- Is there one clear primary action?
- Is the hierarchy obvious in 2 seconds?
- Does it mostly use native patterns?
- Can 20–30% of UI be removed?
- Is the copy short and useful?
- Would someone trust this app daily?
